## Acceptance
1. Slot has `size_ticks` (default 5) and optional `tick_quality`. `validate()` rejects with reasons: size_sum (≠30), size_range (outside 0-30), quality length ≠ size.
2. A legacy 6×5 wheel gives all 30 ticks identical `slice_at`, `offset` and `tier` to the old tables.
3. Sizes [6,4,4,6,4,6] map every tick 0-29 to exactly one slice. No code uses `5 * i` or `round(t / 5)`.
4. Default sub-tick maps match the R11 table for sizes 2-7 (4 = W G G W, no Perfect). A test pins the even-size centre rule.
5. A 0-size slot owns no tick, is never landed on, and draws no wedge.
6. Mirror, flip, snap, nudge and spin are involutions or deterministic on uneven wheels. Mirror and Shunt use the actual neighbor index.
7. Snap lands on the nearest tick. Neighbor resize is fixed and the sum stays 30. A shop overwrite keeps the sum at 30.
8. The slice cap is a config value (default 30 ticks / min size 1, a placeholder). Every `content/enemies` file still validates.
9. The status remap (R6) uses each slice's centre tick.
10. A Calibrated step raises each sub-tick one tier via a config-driven function, with no UI warnings.
11. A save with slots lacking `size_ticks` loads as 5-tick slots. The save version bumps only if the format changes.
12. Wedge angles and the loadout sub-tick map (e.g. `W G P G W`) derive from WheelMath boundaries. Text goes through TextDb in US English.
13. Preview equals result across 200 seeded layouts.
