# test plan: N10 Parasite ring

## 1. What is a rule here

**Rule-bearing (unit tests, `scripts/core` + data validation):**
- `parasite_segment_data.gd`: `validate()`, field defaults, and the effect list (anti-slice effects).
- `wheel_state`: ring storage, `latch`, `remove`, `rotate`, `segment_at(tick)`, the cap (max 2 per the Meridian draft), and serialization.
- `combat_resolver._collect_resolutions`: reading a segment when the player's pointer lands on it, resolution order, and tie-breaks.
- `effect_interpreter`: `LATCH_PARASITE` and the anti-slice effects (damage to the player, −% to the player's damage, apply or remove a status via N8/N9, drain RAM). Cleanse removing a segment.
- The preview: it must call the same resolution path as the result.
- Save/load of the ring (and the save version if the schema bumps).
- Hub/Class interactions: SANDBOX negation (N14), pierce, and the `output_scale` / amount-mode arithmetic (N1).

**View glue (flow test only, no unit tests):** `ring_mods.gd` and `wheel_face.gd` rim art, hover/tooltips, the segment badge, and the preview chip. One scene flow test checks that the nodes exist, the counts match state, and the rim rotates with the wheel.

Assumption: segments are tick-range arcs in the wheel's own frame (Q10 proposal: the ring rotates with the player's wheel).

## 3. Cases

**test_parasite_segment_data.gd**
1. `test_valid_segment_passes_validate`: a 4-tick drain-RAM segment returns no errors.
2. `test_zero_ticks_rejected_names_reason`: error contains "size_ticks".
3. `test_size_over_30_rejected`: 31 ticks fails; 30 passes (edge).
4. `test_empty_effect_list_rejected`: error contains "effects".
5. `test_unknown_effect_type_rejected`: error names the effect.
6. `test_percent_amount_over_100_rejected`: a damage-reduction value above 100 is rejected.
7. `test_latch_effect_on_player_wheel_ok_on_enemy_wheel_rejected`: target validation.
8. `test_validate_content_script_includes_parasite_data`: a bad `.tres` in the fixtures makes the validator return non-zero.

**test_parasite_ring_state.gd**
1. `test_latch_adds_segment_at_tick_range`: latch (start 6, size 4); `segment_at(7)` returns it, `segment_at(10)` returns null.
2. `test_cap_two_third_latch_refused`: the third latch returns false and state is unchanged.
3. `test_latch_overlap_replaces_or_refuses_per_rule`: pin the chosen behavior (assume refuse with a reason string).
4. `test_segment_rotates_with_wheel_spin`: spin +5, the same segment now reads at the shifted pointer tick.
5. `test_flip_mirrors_segments`: after a Flip, a segment at ticks 6–9 maps to the mirrored range, matching the WheelMath formula.
6. `test_nudge_moves_segment_one_tick`: ±1 equals the wheel rotation.
7. `test_wrap_around_segment_29_to_2`: a segment crossing tick 0 reads correctly at 29, 0, 1.
8. `test_remove_segment_by_id`: the ring shrinks and the hash changes.
9. `test_ring_hash_includes_segments`: two states differing only in ring give different hashes.
10. `test_empty_ring_hash_equals_pre_n10_hash`: the empty-ring hash is identical to the old state's, so old replay goldens stay valid (if the hash omits an empty ring).

**test_parasite_resolution.gd**
1. `test_pointer_on_segment_applies_effect`: a damage segment of 3 with the pointer on it takes 3 HP from the player.
2. `test_pointer_off_segment_no_effect`: the pointer one tick outside it, no effect.
3. `test_damage_scaled_by_tier_factor`: a flat 3 at tier 3 (×1.69) = 5; a PERCENT amount isn't rescaled (N1/R2).
4. `test_reduce_player_damage_minus_50pct`: a 10-damage slice resolves as 5 while the segment is read.
5. `test_drain_ram_floor_zero`: drain 2 at 1 RAM leaves 0, not negative.
6. `test_apply_status_segment_stacks_output_down`: one stack added to the slice under the pointer, via N8.
7. `test_remove_status_segment_strips_one_stack`.
8. `test_sandbox_negates_parasite_attack_segment`: attack-type effects are negated whole; non-attack effects (drain) are not.
9. `test_block_absorbs_segment_damage_pierce_ignores`: pierce segment damage bypasses BLOCK and SHIELD.
10. `test_two_segments_same_pointer_resolve_in_order`: the order is segment id ascending; a second pointer resolves after.
11. `test_multiple_pointers_each_read_ring`: with a 2-needle player wheel (N11), each pointer reads the segment independently.
12. `test_segment_resolves_after_slices_in_pass`: pin the pass order (defensive, offensive, then statuses/parasites).
13. `test_cleanse_removes_chosen_segment`: Cleanse targeting a segment removes it, and a later read does nothing.
14. `test_cleanse_prefers_segment_over_status_only_when_chosen`: the CHOSEN picker lists both.
15. `test_latch_effect_from_enemy_slice_adds_segment`: an enemy slice with `LATCH_PARASITE` resolves and the ring has +1.
16. `test_latch_on_dead_player_noop`.

**test_parasite_preview_replay.gd**
1. `test_preview_equals_result_damage_segment`: compare the preview's player HP delta with the real one after End Turn.
2. `test_preview_equals_result_after_nudge_into_segment`: stage a nudge onto a segment and check the preview matches.
3. `test_preview_lists_segment_in_breakdown`: the preview dictionary has a "parasite" entry with the id and amount.
4. `test_undo_nudge_restores_ring_read`: the staged read is removed after undo; the state hash equals the pre-nudge hash.
5. `test_rewind_does_not_cross_checkpoint_with_latch`: a latch happens at resolve, the next start-of-turn respin sets a checkpoint, and rewind stops there.
6. `test_latch_uses_named_rng_stream_only`: with the global `randi` seed changed, the outcome is identical; the stream counter advances only if the segment placement is random (assert it uses the `combat` stream via `RngService`).
7. `test_seeded_replay_equal_hash_with_latches`: record a 6-turn fight against a Meridian-style latcher, replay, compare final hashes.
8. `test_two_seeds_differ_when_latch_random`: proves the seed matters.

**test_parasite_save_migration.gd**
1. `test_ring_round_trip_equal`: save/load mid-combat with 2 segments; the hash is equal.
2. `test_old_save_loads_empty_ring`: a fixture from the previous save version loads with no segments and no errors.
3. `test_version_bumped_only_if_schema_changed`: assert `SAVE_VERSION` against the expected constant.
4. `test_mid_resolve_quit_resume_same_result`: resume leaves the same HP and ring.

**test_parasite_content_sweep.gd (full)**
1. `test_every_latching_enemy_validates`: iterate the registry, find the `LATCH_PARASITE` users, `validate()` all.
2. `test_sweep_fight_never_exceeds_cap_or_negative_ram`: a bot plays 20 seeds per enemy; invariants hold every turn.
3. `test_sweep_replay_deterministic`: two runs per seed produce an identical hash.

**test_parasite_ring_flow.gd**
1. `test_rim_segments_match_state_count`.
2. `test_rim_rotates_with_wheel_spin`.
3. `test_hover_segment_shows_effect_text_us_english`.
4. `test_cleanse_card_picker_offers_segments_keyboard_and_mouse`.
5. `test_preview_chip_shows_parasite_line`.

## 4. Fixtures and helpers

- `tests/fixtures/parasite/`: `seg_damage3.tres`, `seg_drain2.tres`, `seg_bad_*.tres`, and `save_v_prev.json` (a pre-N10 save).
- `tests/helpers/parasite_helper.gd`: `make_combat(seed, segments)`, `latch(state, start, size, effects)`, and `play_turn(state, inputs)`. Use `bounded_wait.gd` for scene awaits (a settle loop with a frame cap, never an unbounded `await`).
- Seeds: 1000, 1001, 1002 (fast); 1000–1019 (sweep).

## 5. Existing tests likely to break

- `test_wheel_math.gd`, `test_rewind.gd`, `test_replay.gd`, `test_preview.gd`: if the state hash or the preview dictionary gains ring fields. Adapt the goldens, and keep the empty-ring hash stable to avoid churn.
- `test_statuses.gd`: PARASITE status semantics (R8/N9, becomes OUTPUT_DOWN ×2) and the Botnet Parasite drone hook. Grep `Status.PARASITE`.
- `test_drones.gd`, `test_breaker.gd`: Cleanse behavior if it now offers segments.
- `test_save_service.gd`, `test_boss_save_writer.gd`: the save version and key lists.
- `test_us_english.gd`, `test_codex_terms.gd`: new strings and Codex entries.
- `test_w2_a5a6_ring.gd`, `test_ring_segments.gd`, `test_art2_wheel_stack.gd`, `test_parity_wheel.gd`: rim layout and node counts.
- `test_keyboard_combat.gd`: the Cleanse picker focus order.

## 6. Order

Write `test_parasite_ring_state.gd` cases 1, 4, 7 and 10 first: they prove the geometry (rotation, wrap) and that the empty-ring hash is unchanged, before any resolver code exists. Then write `test_parasite_preview_replay.gd` case 1 (preview = result) as the failing contract the resolver must satisfy.

Q: Do segments overlap-refuse, replace, or stack when a latch lands on an occupied range?
Q: Does a latch's placement draw from an RNG stream, or is it deterministic (the pointer tick)? This decides tests 6 and 8.
Q: Do parasite attack effects count as "attacks" for SANDBOX in all cases, or only the damage-type ones?
