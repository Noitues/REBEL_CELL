# test plan: N8 ×N status stacks

## 1. What is a rule here

**Rule-bearing (unit tests):**
- `wheel_state` slot-status storage: `{status: stacks}`, the 13 call sites (read, write, clear, merge, iterate).
- `effect_interpreter.apply_status` (stack add, cap, ENCRYPTED absorb) and `cleanse` (remove one stack vs all).
- Output math that reads stacks (PARASITE/OUTPUT_DOWN: −25 % per stack, floor at 0; today's PARASITE = 2 stacks).
- Preview paths that read stacks (`combat_resolver` preview, the HUD result chip's inputs).
- `save_service` v2 → v3 migration and the v3 writer/reader.
- Snapshot, rewind and replay state hash (stacks must be in the hash, in sorted key order).
- Status/stack ordering for iteration (sort by status enum int, never Dictionary insertion order).

**View glue (flow test only):** the ×N badge on the wheel slice, the tooltip text, the Codex line. Check one visible badge text per stack count and that the wheel face builds with stacks.

**Data-only fallback:** none named. N8 is the prerequisite for N9.

## 3. Cases

### test_status_stacks.gd
1. `test_apply_status_on_empty_slice_sets_one_stack`: apply OUTPUT_DOWN ×1; stacks == 1.
2. `test_apply_status_twice_adds_stacks`: apply ×1 twice; stacks == 2.
3. `test_apply_status_amount_three_sets_three`: amount 3 on an empty slice; stacks == 3.
4. `test_stacks_cap_at_config_max`: apply 10; stacks == `status_stack_cap` (placeholder 5). Edge: cap−1, cap, cap+1.
5. `test_zero_stacks_apply_is_noop`: amount 0; the key is absent, not `{S: 0}`.
6. `test_multiple_status_types_coexist_on_slice`: CORRUPTED ×1 and OUTPUT_DOWN ×2; both read back.
7. `test_cleanse_removes_all_stacks_by_default`: ×3 → absent.
8. `test_cleanse_one_stack_mode_decrements`: ×3 → ×2; ×1 → absent (key deleted).
9. `test_encrypted_absorbs_one_apply_regardless_of_amount`: ENCRYPTED, apply OUTPUT_DOWN ×3; stacks 0, ENCRYPTED consumed.
10. `test_encrypted_stacks_absorb_that_many_applies`: ENCRYPTED ×2, two applies absorbed, the third lands.
11. `test_has_status_true_for_any_stacks_ge_one`: legacy `has_status` helper still works.
12. `test_status_iteration_order_is_enum_sorted`: insert in reverse; iteration order by int.
13. `test_overclocked_burnout_converts_to_corrupted_one_stack`: OVERCLOCKED ×1 triggers → CORRUPTED ×1, OVERCLOCKED gone.
14. `test_overclocked_stacks_do_not_multiply_beyond_one_point_five`: ×2 still 1.5× (the rule is not stack-scaled unless stated).
15. `test_flip_and_spin_carry_stacks_with_slice`: the slice moves, stacks unchanged.
16. `test_satellite_slice_statuses_use_stack_form`: the satellite wheel holds the dict form too.

### test_status_stack_math.gd
1. `test_parasite_legacy_equals_output_down_two`: a slice of 10 damage gives 5 (×0.75² = 5.625 → 5, rounding per the existing rule).

3. `test_output_down_floors_at_zero_never_negative`: stacks 5+ on base 1 → 0, never negative.
4. `test_preview_equals_result_with_stacks`: ×3 on the pointer slice; the preview chip damage == the damage dealt after resolve.
5. `test_preview_equals_result_stacks_plus_weak_tier`: WEAK 0.5× combined with ×2; exact int equality.
6. `test_preview_updates_after_cleanse_card`: staged cleanse changes the preview; undo restores it.
7. `test_hardened_encrypted_firmware_absorbs_stack_apply`: permanent ENCRYPTED re-arms.
8. `test_stacks_on_enemy_wheel_reduce_enemy_output`: symmetric with the player.

### test_status_stack_determinism.gd
1. `test_same_seed_same_inputs_same_state_hash_with_stacks`: a 6-turn scripted fight, run twice; hash equal.
2. `test_hash_differs_when_stack_count_differs`: ×1 vs ×2; hashes differ.
3. `test_hash_independent_of_dict_insertion_order`: the same statuses inserted in two orders; hash equal.
4. `test_apply_status_uses_no_global_randi`: the RNG stream counters are unchanged after apply/cleanse (RANDOM_NON_NULL pick draws only from the named stream).
5. `test_random_non_null_pick_tiebreak_by_slice_index`: seeded, same pick on every replay.

8. `test_staged_cleanse_undo_is_clean`: the hash before == the hash after stage+undo.

### test_save_migration_v3.gd

8. `test_migrated_state_hash_equals_fresh_equivalent`: load v2 fixture, migrate, hash == a hand-built v3 state with the same content.
9. `test_migration_is_idempotent`: migrate(migrate(x)) == migrate(x), and a v3 file is untouched byte for byte.
10. `test_v3_roundtrip_save_load_equality`: save → load → equal state incl. ×3 stacks.
11. `test_v3_json_keys_are_strings_and_reload_as_ints`: Dictionary keys survive JSON as ints.
12. `test_future_version_4_is_rejected_with_named_reason`: error "save_version_too_new".
13. `test_corrupt_v3_negative_stacks_rejected`: reason "invalid_stack_count".
14. `test_corrupt_v3_unknown_status_id_rejected`: reason "unknown_status".
15. `test_failed_migration_leaves_original_file_untouched`: a backup `.v2.bak` is written before overwrite, and the original is intact if migration fails.
16. `test_resume_after_migration_replays_remaining_inputs_equal`: migrate a mid-fight v2 save, continue, compare to the recorded v2 final hash.

## 6. Order
1. Write `test_save_migration_v3.gd` cases 2–4 and 8 and the v2 fixtures first, before any code. They fail on "version" and prove that the old data meaning (PARASITE = OUTPUT_DOWN ×2) is pinned.
2. Then `test_status_stacks.gd` 1–3, 7, then the math table, then determinism and rewind.

Q: Does a stack cap exist, and is it one global value or per status (ENCRYPTED, OVERCLOCKED likely 1)?
Q: Does cleanse remove all stacks or one? That decides cases 7–8.
Q: Should migration keep a `.v2.bak` automatically, or is the failed-migration test only about not overwriting?
