# test plan: N1 Amount modes

## 1. What is a rule here
Rule-bearing (CLAUDE.md rule 6) and unit-tested:
- `EffectData` / `SliceData` new fields `amount_mode` (FLAT / PERCENT) and their `validate()`.
- `effect_interpreter._scaled`, `heal`, `gain_block`, `gain_shield` (and the corruption count path where PERCENT means a share of non-NULL slices, R5).
- `combat_resolver._resolve_pointer` / `_slice_action`: carrying the mode into the interpreter, and the preview path that shares it.
- Tier damage factor lookup via `enemy_output_scale()` (the factor table `enemy_damage_by_tier` is N2; N1 reads a factor and is tested with a stub table).
- `shield_cap` interaction (15 applies to the player; an enemy percent-shield cap is Q9, not tested).

View glue (flow test only, no unit tests): result chips, tooltips and Codex text that display the amounts. They only need one check that the chip shows the interpreter's number.

Arithmetic contract under test:
- FLAT enemy amount = round(base × tier factor), with the factor table [1.0, 1.3, 1.69, 2.2].
- PERCENT = floor or round(owner max HP × pct/100), never scaled again; the rounding rule is fixed in one test (round half up, minimum 1 when pct > 0).
- Player FLAT amounts are unscaled.
- Buffs and debuffs are tier-independent.
