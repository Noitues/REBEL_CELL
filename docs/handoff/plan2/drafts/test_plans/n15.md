# test plan: N15 Rim gates

## 1. What is a rule here
Rule-bearing (CLAUDE.md rule 6), so unit-tested:
- `WheelData` gate fields and `validate()`: gate ticks, effect, and the per-wheel gate cap.
- `WheelMath.gates_crossed(start_rot, delta, pointer_ticks, gate_ticks)`: a pure function with no state and no RNG.
- `effect_interpreter.nudge` / `spin`: calls traversal and fires gate effects. `flip`, `snap_to_center`, `respin` and `freeze` never call it.
- The preview path in the resolver: it must report the same crossed-gate list the real action produces.
- Gate state in the save and the state hash, if a gate carries a counter. That counter is the Orbital countdown; if it lives in listener or boss state, test it in that system's file.

View glue gets one flow test only: the `ui/wheel` gate glyph and the lit-on-preview state.

Semantics fixed here (pending the Q: lines):
- A gate is crossed when its tick is *entered* under a pointer during a move. The start tick is excluded and the end tick is included.
- Each pointer is checked separately, so a wheel with 2 pointers can cross the same gate twice in one move.
- Only ticks actually moved count. Ticks absorbed by resistance do not.
- Gates sit on the outer ring only; inner-ring nudges never traverse.

## 3. Cases

**test_rim_gate_math.gd**
1. `test_nudge_plus1_onto_gate_tick_crosses`: gate 10, pointer 0, rot 9, +1. Expect `[10]`.
2. `test_start_tick_on_gate_not_counted`: start on gate 10, nudge +1. Expect `[]`.
3. `test_nudge_minus1_onto_gate_crosses`: gate 10, rot 11, −1. Expect `[10]`.
4. `test_spin_5_passes_two_gates_in_order`: gates 3 and 4, rot 0, +5. Expect `[3,4]`.
5. `test_wrap_29_to_1_crosses_gate_0`: gate 0, rot 29, +2. Expect `[0]`.
6. `test_negative_wrap_crosses`: gate 29, rot 1, −3. Expect `[29]`.
7. `test_full_revolution_30_crosses_each_gate_once`: gates {0,10,20}, +30. Expect 3 crossings.
8. `test_spin_60_crosses_each_gate_twice`: same gates, +60. Expect 6.
9. `test_zero_delta_crosses_nothing`: edge 0.
10. `test_two_pointers_cross_same_gate_twice`: pointers {0,14}, a move that brings the gate under both. Expect 2 entries, ordered by pointer index.
11. `test_no_gates_returns_empty`.
12. `test_crossing_order_is_tick_order_then_pointer_index`: the deterministic tie-break.

**test_rim_gate_data.gd**
1. `test_validate_rejects_gate_tick_out_of_range`: tick 30 and −1 each fail, reason "gate tick out of 0..29".
2. `test_validate_rejects_duplicate_gate_ticks`: reason "duplicate gate tick".
3. `test_validate_rejects_gate_with_no_effect`: reason "gate has no effect".
4. `test_validate_rejects_more_than_max_gates`: cap 4, so 5 fails.
5. `test_validate_accepts_zero_gates`: legacy wheels unchanged.
6. `test_all_content_wheels_validate`: the `validate_content` path stays green.

**test_rim_gate_actions.gd**
1. `test_nudge_across_gate_applies_effect_once`: gate effect "deal 6 to the owner". Assert exact HP −6.
2. `test_spin_across_two_gates_applies_both_in_order`: 12 HP lost and the order recorded.
3. `test_spin_with_resistance_2_counts_only_moved_ticks`: spin 5, resistance 2, gate at the 4th tick. Expect no crossing; gate at the 3rd tick. Expect a crossing.
4. `test_fully_absorbed_nudge_crosses_nothing`: resistance 1, nudge 1.
5. `test_flip_never_crosses_gate`: Flip moves the gate under the pointer. Expect no effect.
6. `test_snap_to_center_never_crosses`.
7. `test_respin_never_crosses_gate`: 30 seeded respins, zero effects. This is the headline negative.
8. `test_start_of_turn_respin_never_crosses`.
9. `test_freeze_never_crosses`.
10. `test_inner_ring_nudge_never_crosses`.
11. `test_nudge_then_undo_restores_hp_and_counter`: undo-clean.
12. `test_gate_fires_per_action_not_per_turn`: 3 paid nudges, 3 crossings.
13. `test_gate_effect_cannot_cross_phase_floor`: a gate hit at the R3 parked floor leaves HP at the floor.
14. `test_free_nudge_flag_unchanged_by_gate`: the gate does not change nudge costs.

**test_rim_gate_preview.gd**
1. `test_card_hover_preview_lists_crossed_gates_equal_to_actual`: hover a spin card, snapshot the list, play it, compare.
2. `test_nudge_preview_equals_result_hp`: predicted HP after equals actual HP.
3. `test_preview_does_not_mutate_state`: state hash before equals state hash after the preview.
4. `test_preview_of_flip_shows_no_gates`.
5. `test_preview_respects_resistance`: matches case 3 above.
6. `test_preview_with_staged_prior_action`: stage nudge A, then preview card B. The start rotation is the staged one.
7. `test_preview_flags_lethal_gate_damage`.

**test_rim_gate_determinism.gd**
1. `test_replay_same_seed_same_inputs_same_hash`: a scripted 12-action turn with gate crossings, run twice.
2. `test_different_seed_changes_respin_not_gate_rule`: gate counts depend only on rotation.
3. `test_gate_resolution_uses_no_global_randi`: grep-style test plus an RngService draw-count assertion (0 draws by gate code).
4. `test_rewind_to_checkpoint_restores_gate_counter`.
5. `test_rewind_cannot_cross_checkpoint_after_respin_with_gates`.
6. `test_save_load_mid_combat_preserves_gate_state`: round-trip equality. If the save version is unchanged, assert old saves load with gates empty.
7. `test_content_id_then_node_id_tie_break`: two wheels cross a gate in one resolve. Effects apply in content id order, then node id.

**test_rim_gate_sweep.gd** (full)
1. `test_all_starts_and_deltas_match_bruteforce`: 30 starts × deltas −35..35 × pointer sets {[0], [0,14], [0,10,20]}. Compare against a one-tick-at-a-time stepper.
2. `test_math_is_symmetric_under_reversal`: crossings of (+d) from s equal reversed crossings of (−d) from s+d, except for the start/end inclusion rule.

**integration/test_rim_gate_flow.gd**
1. `test_gate_glyph_drawn_at_tick`: a wheel with a gate renders a node at the tick angle (12° × tick).
2. `test_hover_nudge_lights_gate_then_clears`: via `bounded_wait`.
3. `test_keyboard_nudge_fires_gate_and_log_line`: keyboard only.

- Seeds: 1, 7, 1000.

## 5. Existing tests likely to break
- `test_wheel_math.gd`: if the signatures of `WheelMath` helpers change, adapt them. Add no gate assertions there.
- `test_resistance.gd`, `test_preview.gd`, `test_rewind.gd`, `test_replay.gd`, `test_respin_action.gd`: any hard-coded state-hash or serialized-wheel fixture breaks if `WheelData` gains a field. Regenerate the goldens and diff them for a pure addition.
- `test_save_service.gd`, `test_boss_save_writer.gd`: the serialized wheel dictionary gets a new key. Allow it missing on load.
- `test_content_registry.gd`, `test_corporations.gd`, `test_suite_integrity.gd`: new test files must be added to the manifest, and new content must validate.
- `test_w2_a5a6_ring.gd`, `test_parity_wheel.gd`, `test_art2_wheel_stack.gd`: the wheel node tree may gain a gate layer. Grep for child-count asserts.
- Grep for `deal_hit(` in tests that check HP after a nudge: they must stay green on gate-free wheels.

## 6. Order
1. Write `test_rim_gate_math.gd` case 1, then the `test_rim_gate_sweep.gd` brute-force oracle. Before any code is done, these fix the entered-tick semantics and prove the pure function matches a stepper.
2. Next, `test_respin_never_crosses_gate` (action case 7). It protects the one hard rule from the start.
3. Then preview equals result, then determinism, then the flow test.

Q: Does a gate on the end tick count as crossed, or only strictly passed? The tests assume it counts.
Q: Does a gate fire once per pointer, or once per action regardless of pointers?
Q: Do a satellite's mini-wheel nudges traverse their own gates?
