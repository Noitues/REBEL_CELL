# test plan: N2 Tier base-value tables

## 1. What is a rule here
Rule-bearing (CLAUDE.md rule 6), unit tested:
- `EnemyData.hp_by_tier` (4 entries) and `EnemyData.validate()` band checks per class (R1/R2 table).
- Boss `hp_bands`: {zone ceiling, HP} lookup keyed on the ICE boss-strength multiplier.
- `CampaignConfigData`: `enemy_damage_by_tier` = [1.0, 1.3, 1.69, 2.2], `reference_dpt_by_tier` = [9, 11, 14, 18], `target_turns_per_phase` = 3.5, and the band-lint helper that computes the allowed range.
- `NetrunSession.enemy_scale()` (HP) and `enemy_output_scale()` (damage), now table reads.
- `CombatResolver.create_combat`: starting HP from the table, flat-amount scaling input.
- The lint test over every `content/enemies/*.tres`.

View glue (flow test only, no unit tests): any HP or tier text on codex or map screens that merely reads the value.

Out of scope: N1 amount-mode arithmetic (flat × tier factor) beyond the scale accessor it will call.

## 3. Cases

**test_tier_tables.gd**
1. test_damage_table_default_values_exact: load `campaign_config.tres`; assert [1.0, 1.3, 1.69, 2.2].
2. test_reference_dpt_default_values_exact: assert [9, 11, 14, 18].
3. test_target_turns_per_phase_is_3_5: assert the value.
4. test_damage_table_matches_old_formula: for t in 0..3 assert abs(table[t] − 1.3^t) < 0.05 (2.2 vs 2.197).
5. test_schema_default_not_1_6: a fresh `CampaignConfigData.new()` has the same table, so no stray default survives.
6. test_tier_index_clamps: accessor with tier 0, 5 and −1 clamps to the ends (edge values).
7. test_config_validate_rejects_wrong_length: 3-entry table gives "enemy_damage_by_tier must have 4 entries".
8. test_config_validate_rejects_non_monotonic: [1.0, 0.9, …] gives "enemy_damage_by_tier must be non-decreasing".
9. test_config_validate_rejects_zero_or_negative: 0 in dpt gives "reference_dpt_by_tier must be > 0".

**test_enemy_hp_bands.gd**
1. test_normal_validate_accepts_in_band: normal T3 HP 50 passes; edges 44 and 56 pass.
2. test_normal_validate_rejects_below_band: T3 43 gives reason "hp_by_tier[2] 43 outside normal band 44-56".
3. test_normal_validate_rejects_above_band: T3 57 is rejected.
4. test_elite_band_edges_t1_to_t4: 56/72, 68/88, 88/112, 112/144 accepted; each minus 1 and plus 1 rejected.
5. test_miniboss_2_and_3_phase_bands: 2 phases at T2 77 passes; 3 phases at T2 116 passes; 77 on a 3-phase mini-boss is rejected.
6. test_miniboss_rejects_t4_entry: a T4 value gives "mini-boss has no T4 band".
7. test_hp_by_tier_wrong_length_rejected: 3 entries gives "hp_by_tier must have 4 entries".
8. test_boss_hp_bands_lookup_zones: bands {1.00:300, 1.15:330, 1.30:360, 99:400}. Multiplier 1.00→300, 1.01→330, 1.15→330, 1.30→360, 1.31→400.
9. test_boss_hp_bands_must_be_sorted: unsorted ceilings give "hp_bands ceilings must ascend".
10. test_boss_hp_bands_last_ceiling_open: no catch-all gives "hp_bands must cover multiplier > last ceiling".
11. test_boss_band_checks_phase_budget_sum: bands outside the sum of phase budgets (R2) are rejected; Genome Core 300 passes.
12. test_normal_with_phase_entries_rejected: keeps the existing R1 rule (one phase entry on elites, none on normals).
13. test_legacy_hp_field_fallback: the data-only fallback. With empty `hp_by_tier`, `validate()` accepts `base_hp` and `create_combat` uses the old multiplier. This is a documented migration shim, removed once the lint is green on all 57 enemies. Assert both paths yield the same HP at T1.

**test_enemy_scale_tables.gd**
1. test_output_scale_returns_table_value_per_tier: tiers 1..4 give 1.0, 1.3, 1.69, 2.2.
2. test_flat_amount_times_output_scale_exact: heal 10 at T3 → round(10 × 1.69) = 17 (via the accessor; the rounding rule is pinned here).
3. test_percent_amount_not_rescaled: 2 % of max HP 300 at T4 is 6, independent of the table (guards the R2 "never scaled again" rule).
4. test_create_combat_enemy_hp_from_hp_by_tier: a 4-entry fixture enemy gets [30, 40, 50, 60]; assert HP per tier.
5. test_create_combat_boss_hp_from_band_and_ice: ICE 0 → 300; ICE with +20 % → 330 (zone ≤ 1.30 gives 360 for 1.2; pin exact).
6. test_enemy_scale_hp_no_longer_multiplies: with `hp_by_tier` set, the old HP multiplier has no effect (assert unchanged when config is altered).
7. test_buffs_tier_independent: ×1.25 stays ×1.25 at T1 and T4.
8. test_tier_out_of_range_clamps_no_crash: tier 0 and tier 9 give end values, no error.

**test_tier_tables_replay.gd**
1. test_same_seed_same_state_hash: a fixed seed and an input script for a T3 fight run twice give equal hashes.
2. test_no_global_randi_in_scaling: grep the two accessors plus `create_combat` source for `randi(`/`randf(` (static check).
3. test_preview_damage_equals_result_at_each_tier: for T1..T4, the enemy hit preview equals the actual HP loss (reuse the test_preview.gd helper).
4. test_save_round_trip_preserves_scaled_hp: save mid-fight at T4, load, compare HP, max HP and hash.
5. test_old_save_loads_with_table_hp: a v-current save made before N2 loads without error; its stored max HP is kept, not recomputed.
6. test_tie_break_order_stable: enemies sorted by content id, so the lint report is deterministic across two runs.

**test_band_lint.gd**
1. test_every_enemy_validates: iterate the registry; assert `validate()` empty. Pending enemies are listed in an explicit allowlist file that may only shrink.
2. test_allowlist_only_shrinks: allowlist ids all exist and still fail (stale entries are errors).
3. test_all_normals_one_phase_in_band: T1..T4 bands.
4. test_all_elites_two_phase_in_band.
5. test_bosses_have_four_hp_bands.
6. test_phase_budget_matches_config: for the Genome Core compute (18−3)×3.5 = 52.5 → 52 and check the P1 span against the threshold.
7. test_lint_report_names_enemy_and_tier: the failure message contains id and tier.

**test_tier_tables_flow.gd**
1. test_netrun_t1_and_t4_fight_hp_matches_table: run to the first combat at T1 and at T4 on a seeded session; assert enemy HP against the fixture.
2. test_validate_content_tool_passes: run `tools/validate_content.gd` equivalent; no errors.

- test_campaign_config.gd: asserts the old 1.3 or 1.6 scale; update it to the table.
- test_ice_combat.gd and test_ice_campaign.gd: boss HP × strength expectations; move them to band lookups.
- test_boss.gd, test_enemies_m2.gd, test_solace_content.gd, test_rebel_cell.gd: hard-coded HP (1,475 Genome Core, 271–287 elites).
- test_balance_sim.gd and test_simulation.gd: sim-derived numbers; re-baseline.
- test_content_registry.gd, test_combat_content.gd: validation on all enemies; add the allowlist.
- grep `enemy_scale`, `enemy_output_scale`, `max_hp` and `1.3` in tests/.

## 6. Order
First: test_tier_tables.gd cases 1–2 and test_enemy_hp_bands.gd 8 (zone lookup). They fail to compile or load before any code exists. They pin the three agreed tables and the one lookup rule, so the draft's HP and damage numbers are fixed before the lint ever runs.

Q: Does the boss band zone read the ICE multiplier after the Heat and campaign modifiers, or the ICE term only?
Q: Should the allowlist be a hard CI gate, or a warning until the design pass finishes?
