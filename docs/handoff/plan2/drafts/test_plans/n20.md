# test plan: N20 Slice riders

## 1. What is a rule here

**Rule-bearing (unit tests):**
- `slice_data` rider fields and `validate()`: `hits` (int), `hits_per_target_status` (status enum + per-stack count), `perfect_multiplier` (float), `pierce` (bool).
- `combat_resolver._resolve_pointer` and `_slice_action`: how riders turn one landing into hit lists, multipliers and pierce flags.
- `effect_interpreter.deal_hit`: consumes the pierce flag. Per R13, pierce ignores BLOCK and SHIELD but not SANDBOX or bodyguards.
- The preview path that reuses the same resolver code.
- The N9 dependency: the status count read by `hits_per_target_status` (CORRUPTED slices on the target wheel). Exercised through a helper, not re-tested.

**View glue (flow test only):**
- Rider text on slice tooltips and chips: "3 × 2", "×4 on Perfect", "PIERCE".
- Preview breakdown chip layout.

**Data-only fallback:** none named. The riders exist only as fields, and nothing can be authored without them. The fallback to test is "all riders at defaults behaves exactly like today."

## 3. Cases

**test_slice_riders_data.gd**
1. `test_defaults_leave_slice_unchanged`: new SliceData has hits=1, per-status=none, perfect_multiplier=1.0, pierce=false.
2. `test_validate_rejects_hits_zero`: hits=0 → reason "hits must be >= 1".
3. `test_validate_rejects_negative_perfect_multiplier`: −1.0 → reason "perfect_multiplier must be > 0".
4. `test_validate_rejects_hits_per_status_without_status`: count set, status NONE → named reason.
5. `test_validate_rejects_hits_on_non_damage_slice`: DEFRAG with hits=3 → "riders need a damage slice".
6. `test_validate_accepts_hits_cap`: hits=8 passes, hits=9 fails (placeholder cap `MAX_HITS`=8).
7. `test_tres_round_trip_keeps_riders`: save and load a slice and compare every field.
8. `test_validate_content_all_slices_pass`: the existing content sweep still passes.

**test_slice_riders_resolve.gd**
1. `test_hits_3_deals_three_separate_hits`: base 5 damage, hits=3, no block → 3 hit events of 5, total 15.
2. `test_hits_each_hit_absorbed_by_block_separately`: BLOCK 7, 3×5 → 5 absorbed, 2 through, then 5, 5 = 12 HP lost.
3. `test_hits_1_matches_legacy_result`: output equals the pre-rider golden numbers.
4. `test_hits_per_status_scales_with_corrupted_count`: IV 2 damage, 3 CORRUPTED slices → 3 hits of 2 (R-spec Genome Core IV).
5. `test_hits_per_status_zero_stacks_uses_min_1`: 0 CORRUPTED → 1 hit (draft's "min 1").
6. `test_hits_per_status_counts_stacks_after_n8`: a ×2 stack counts as 2 (guarded; skipped if N8 absent).
7. `test_hits_per_status_max_6_slices`: 5 non-NULL CORRUPTED slices → 5 hits (edge max).
8. `test_perfect_multiplier_4_on_perfect`: base 10, PERFECT → 40.
9. `test_perfect_multiplier_ignored_on_good_and_weak`: GOOD 10, WEAK 5 (0.5× tier first, no ×4).
10. `test_perfect_multiplier_stacks_with_output_down`: 40 × 0.75 (OUTPUT_DOWN) = 30 exact.
11. `test_perfect_multiplier_with_enemy_damage_factor_t3`: 10 × 4 × 1.69 = 67.6 → rounding rule asserted, same as the existing `_scaled` rounding.
12. `test_pierce_ignores_block_and_shield`: BLOCK 8 + SHIELD 5, hit 10 → 10 HP lost, block and shield untouched.
13. `test_pierce_does_not_bypass_sandbox`: SANDBOX negates the whole resolution.
14. `test_pierce_does_not_bypass_satellite_guard`: the hit lands on the guard.
15. `test_pierce_with_hits_applies_to_every_hit`: 3 pierce hits of 5 → 15.
16. `test_riders_combine_hits_pierce_perfect`: hits=2, ×4, pierce on Perfect → 2 hits of 4×base, both piercing.
17. `test_multi_pointer_riders_apply_per_pointer`: two needles on rider slices → each resolves its own hits (the pointer rule).
18. `test_phase_floor_parks_each_hit`: R3 floor with hits=4 near the threshold → the first hit crossing parks, later hits are lost, phase changes once.
19. `test_overclocked_multiplies_rider_output`: 1.5× on top of ×4.

**test_slice_riders_preview.gd**
1. `test_preview_equals_result_hits`: preview total and hit list equal the real resolve.
2. `test_preview_equals_result_pierce_vs_block`.
3. `test_preview_equals_result_perfect_multiplier_after_nudge`: nudge a landing from Perfect to Good, the preview drops ×4 and matches the result.
4. `test_preview_hit_count_updates_when_cleanse_staged`: cleansing a CORRUPTED slice changes the count, and undo restores it.
5. `test_staging_undo_restores_state_hash`: stage, undo, hash equals the start.
6. `test_rewind_does_not_cross_checkpoint`: rider turn after the respin checkpoint, rewind stops at the respin.

**test_slice_riders_determinism.gd**
1. `test_seeded_replay_same_hash`: record inputs for a 5-turn fight with rider slices, replay twice, equal final hashes.
2. `test_riders_use_no_global_randi`: grep-style check of the touched functions plus a counter on RngService draws (riders add 0 draws).
3. `test_hit_order_is_slice_order_then_pointer_index`: tie-break for the event log.
4. `test_equal_resolutions_sorted_by_content_id`: two rider slices at equal priority resolve by id.

**test_slice_riders_flow.gd**
1. `test_rider_slice_tooltip_shows_hits_and_pierce`: US-English strings, no raw field names.
2. `test_full_turn_with_rider_enemy_ends_with_expected_hp`: fixture enemy, End Turn, HP asserted.

**test_slice_riders_sweep.gd**
1. `test_sweep_riders_preview_equals_result`: hits 1–4 × mult {1, 4} × pierce × tiers × T1–T4 × block {0, 7}, with 1 or 2 pointers.

## 4. Fixtures and helpers
- `tests/fixtures/slices/rider_*.tres`: `rider_hits3`, `rider_iv`, `rider_medicine`, `rider_adrenaline`, `rider_bad_*` for the validation cases.
- `tests/helpers/rider_combat.gd`: builds a CombatState with a chosen enemy slice, tier, block, shield and N CORRUPTED slices, with seed 7; returns the event log and the hash.
- Use `bounded_wait.gd` in the flow test only. Unit tests are synchronous.

## 5. Existing tests likely to break
- `test_resolution_order.gd`, `test_targeting.gd` and `test_statuses.gd`: the hit-event log shape may gain fields. Adapt asserts to read totals.
- `test_preview.gd`, `test_plan1_a2_preview.gd`, `test_w1_tag_preview.gd`: chip breakdown strings.
- `test_boss.gd`, `test_enemies_m2.gd`: golden numbers should not change at defaults. Grep for `deal_hit` mocks.
- `test_replay.gd`: state-hash golden if the hash covers slice fields.
- `test_combat_content.gd`, `test_solace_content.gd`: the validation count.

## 6. Order
Write `test_defaults_leave_slice_unchanged` and `test_hits_1_matches_legacy_result` first. Together they prove that defaults reproduce today's golden resolutions before any rider code exists. Then pierce vs SANDBOX, since it pins the R13 rule.

Q: Does `hits_per_target_status` count stacks (N8) or slices? Tests 4 and 6 assume stacks count.
Q: Do multi-hit riders consume one BLOCK pool in sequence (assumed) or per hit?
Q: Is `perfect_multiplier` applied before or after the WEAK 0.5× tier factor? Not decidable here, since the multiplier only fires on Perfect.
