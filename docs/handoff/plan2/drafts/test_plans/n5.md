# test plan: N5 Boss buffs and Exploits

## 1. What is a rule here

Rule-bearing code (CLAUDE.md rule 6), unit-tested:
- **`BossBuffData` + `EnemyData.buffs`**: `validate()` (named reasons), and buff-state resolution (active or disabled) as a pure function of (enemy, set of owned Exploits).
- **`ExploitData.disables_buff`**: the id link and its validation.
- **`campaign_rules` Grid build**: drawing `exploits_per_grid` (5) Exploits from the corporation pool, via a named RNG stream. Also the breach gate (`min_exploits_for_breach = 3`, kept).
- **Combat-side buff gating**: where `combat_resolver` / `effect_interpreter` read "is buff X active" (hub heal, 2nd needle, resistance, etc.). The gate applies at create_combat and at phase entry, and the preview uses the same function.
- **Breach overrides**: the existing Intel / Breach / Virus overrides become buff disables. Per the Q5 default these stay fixed gate types; this plan assumes so.
- **Save**: `site_data`/Grid state gains the drawn subset. Test the save round trip, and add a migration case only if the save version bumps.

View glue (flow test only, no unit tests): the HQ Exploit list UI, buff chips and tooltips, and the "countered / not countered" badge.

## 3. Cases

**test_boss_buff_data.gd**
1. `test_valid_buff_passes` – a buff with id, effect key, and a counter that exists → no errors.
2. `test_buff_empty_id_rejected` – error names "buff id empty".
3. `test_duplicate_buff_id_on_enemy_rejected` – two buffs share an id → "duplicate buff id".
4. `test_unknown_effect_key_rejected` – reason names the key.
5. `test_disables_buff_dangling_rejected` – an Exploit points to a nonexistent buff → "disables_buff unknown".
6. `test_buff_with_no_counter_exploit_allowed` – the pool may omit a counter; validation warns but passes. Assert that is the designed behavior.
7. `test_exploit_disables_two_buffs_rejected` – one Exploit disables at most one buff.
8. `test_non_boss_with_buffs_rejected` – normals carry no buffs; elites are allowed per draft, so assert the chosen rule explicitly.
9. `test_all_content_buffs_validate` – run validate on every .tres (extends tools/validate_content).

**test_boss_buff_state.gd**
1. `test_buff_active_without_exploit` – boss with Metabolism, owned = {} → active.
2. `test_buff_disabled_with_counter_exploit` – owned = {Exploit A} → disabled.
3. `test_unrelated_exploit_leaves_buff_active`.
4. `test_metabolism_off_removes_hub_heal` – a 2 % PERCENT heal at 300 max HP: active heals 6 per turn; disabled heals 0.
5. `test_second_opinion_off_keeps_one_needle_in_p3` – pointer count 1 vs 2 after the phase override.
6. `test_compliance_lock_off_resistance_zero` – resistance 2 → 0; nudge is not absorbed.
7. `test_triage_reserve_shield_is_five_percent` – 300 max HP → shield 15 (cap 15); at max HP 400 the result is still capped at 15.
8. `test_buff_gate_applies_on_phase_entry` – the buff is re-read after a `wheel_override`, not cached from combat start.
9. `test_preview_equals_result_with_buff_active` – preview chip values equal the post-resolve deltas, with buffs on and off.
10. `test_buff_gate_survives_phase_change_statuses` – the buff state does not reset when R6 keeps statuses.
11. `test_undo_after_card_does_not_change_buff_state` – the buff set is immutable within a combat.
12. `test_hidden_chart_buff_only_affects_visibility` – the intel flag changes the view model, never the rules or state hash.
13. `test_zero_buffs_boss_resolves_as_before` – edge: an empty buff list matches the legacy result hash.

**test_exploit_grid_draw.gd**
1. `test_draw_returns_exactly_five` – a pool of 8 → 5 distinct ids.
2. `test_pool_smaller_than_five_returns_all` – pool of 3 → 3, no error.
3. `test_pool_zero_returns_empty_and_breach_blocked` – edge: empty pool.
4. `test_exploits_per_grid_one_edge` – draws 1.
5. `test_same_seed_same_subset` – two builds with seed S produce an equal ordered list.
6. `test_different_seed_can_differ` – across 20 seeds, at least 2 distinct subsets.
7. `test_draw_uses_named_stream_only` – a spy on RngService records the stream name; the global `randi` is never called (grep the file for `randi(` as a guard).
8. `test_draw_does_not_advance_other_streams` – the state of the map and loot streams is unchanged.
9. `test_tie_break_by_exploit_id_then_node_id` – two Exploits with an equal sort key are ordered by id; two sites ordered by node id.
10. `test_each_t2_site_holds_at_most_one_exploit_still_true` – GDD 4.1 invariant after the draw.
11. `test_breach_opens_at_three_owned` – the gate is closed at 2, open at 3.
12. `test_breach_with_three_irrelevant_exploits_opens` – the gate counts owned, not counters; assert the default under Q.
13. `test_seeded_replay_state_hash_equal` – build the Grid, run inputs, replay: equal hash.

**test_boss_buff_save.gd**
1. `test_grid_subset_round_trips` – save and load; the subset and its order are identical.
2. `test_owned_exploits_round_trip`.
3. `test_loaded_campaign_boss_buffs_match` – the active buff list is equal before and after load.
4. `test_rewind_never_crosses_checkpoint_with_buffs` – a checkpoint inside a buffed fight still blocks undo.
5. `test_old_save_without_subset_rejected_or_migrated` – runs only if the version bumps; D3 drops old saves, so assert a clean refusal with a reason.

**test_boss_buff_sweep.gd** (full)
1. `test_every_boss_every_subset_resolves_without_error` – each boss runs 3 turns with each of C(pool,5) subsets, capped at 56.
2. `test_every_buff_has_at_least_one_counter_in_pool`.
3. `test_no_boss_unwinnable_by_zero_counters` – the sim reaches phase 2 with no counters.

**integration/test_hq_exploit_list.gd**
1. `test_list_shows_five_drawn_exploits`.
2. `test_countered_buff_row_marked` – the row appears after the Exploit is acquired.

## 6. Order
First: `test_buff_active_without_exploit` and `test_buff_disabled_with_counter_exploit`, followed by `test_zero_buffs_boss_resolves_as_before`. Together they prove the gate is a pure function and that legacy bosses keep their hashes before any Grid draw or UI exists. Then the draw determinism cases.

Q: Does any 3 owned Exploits open the breach (assumed yes), or must they counter specific buffs?
Q: Is the drawn subset fixed at campaign start (assumed) or redrawn per boss attempt?
Q: Do elites (Port Authority, Handler Proxy drafts) carry buffs, or only bosses?
