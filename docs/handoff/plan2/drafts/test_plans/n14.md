# test plan: N14 Defense trio

## 1. What is a rule here

**Rule-bearing (unit tests, rule 6):**
- `effect_interpreter.gain_block` (DEFRAG, BLOCK), `gain_shield` (SANDBOX type, now SHIELD) and `gain_evade` (DETOUR type, now SANDBOX). These carry the new "negates one whole attack" semantics.
- `effect_interpreter.deal_hit`: order of checks (SANDBOX, then bodyguard/satellite, then BLOCK, then SHIELD, then HP) and the pierce rule. Pierce ignores BLOCK and SHIELD, but not SANDBOX or bodyguards.
- `combat_resolver._slice_action` and `_resolve_pointer`: a resolution is "one slice, all its hits". Hit grouping must be stable so SANDBOX can negate every hit of one resolution.
- `combat_resolver.start_turn`: BLOCK expiry, SHIELD persistence, SANDBOX expiry.
- Preview path (the same code with `dry_run`): the chips must equal the result.
- Save fields: the evade counter keeps its name and enum ints (SliceType.DETOUR, SANDBOX). No save version change is expected.
- `slice_data.validate` / `EffectData.validate` for enum ints kept.

**View glue (one flow test only, no unit tests):** glyph swaps, Codex entries and strings (display names). The only automated checks are a terms/strings test (existing `test_codex_terms`, `test_us_english`) plus one combat-scene flow test.
