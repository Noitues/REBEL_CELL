# test plan: N16 Events that alter future fights / paths; impromptu fights

## 1. What is a rule here

Rule-bearing (unit tests, per CLAUDE.md rule 6):
- **`EventChoiceData`** (`starts_combat`, `combat_overrides`, `map_edits`): the schema and `validate()`.
- **`netrun_session`**: choice resolution, the run-level `next_combat_overrides` queue (RunState), consumption when a fight is created, and impromptu fight launch and return.
- **`map_graph`**: applying `map_edits`, with reachability and layer invariants.
- **RunState**: serialization, save version, checkpointed RNG use.
- **N2 scaling interaction**: overrides apply after `hp_by_tier` and `enemy_damage_by_tier`, never rescaled.

View glue (one flow test only, no unit tests): the event page's rendering of consequence text and the map redraw after an edit.

Out of scope here: the event wheel (N17), the rewards table (N18), and HQ/raid-view events (those drafts only consume the same session API).

Assumed override fields (placeholders): `enemy_hp_pct` (±), `enemy_damage_pct` (additive step, tier independent), `extra_status`, `enemy_id` swap, `rack_strength`. Assumed `map_edits` ops: `add_node(layer, type)`, `remove_node(id)`, `retype_node(id, type)`, `add_edge(a, b)`, `remove_edge(a, b)`.

## 3. Cases

**test_event_choice_validate.gd**
1. test_default_choice_is_inert_valid: a new choice has no fight, overrides or edits and passes validate.
2. test_starts_combat_without_enemy_rejected: reason "starts_combat needs enemy_id or pool".
3. test_unknown_enemy_id_rejected: reason names the id.
4. test_override_hp_pct_below_minus_50_rejected: -51 fails, -50 passes (edge).
5. test_override_hp_pct_above_100_rejected: 101 fails; 0 and 100 pass.
6. test_override_status_unknown_rejected: bad Status int fails.
7. test_map_edit_unknown_op_rejected: reason "unknown op".
8. test_map_edit_remove_final_rack_rejected: static check on the op targeting the last-layer node.
9. test_override_ttl_zero_rejected: `fights=0` fails, 1 passes.
10. test_all_shipped_events_validate: loop over `content/events`, no errors (also covered by validate_content).

**test_next_combat_overrides.gd**
1. test_override_consumed_by_next_fight_only: queue one, create 2 fights; the first has it, the second is clean, queue empty.
2. test_override_fifo_order: queue A then B; fights 1 and 2 get A then B.
3. test_ttl_two_applies_to_two_fights: `fights=2` applies to both, then drops.
4. test_hp_pct_arithmetic_exact: T3 normal, `hp_by_tier[2]=50`, +20 % → 60; -20 % → 40; 0 → 50.
5. test_hp_pct_rounds_half_up_min_one: 3 HP base with -50 % → 2 (rounded), a 1-HP result stays ≥ 1.
6. test_damage_step_not_rescaled_by_tier: base dmg 5 at T4, factor 2.2, +25 % step → 5×2.2×1.25 and not ×2.2 twice. Check against hand value.
7. test_override_stacks_additive_with_enrage: +25 % override plus enrage step 1 gives ×1.5 (additive, per R4 default).
8. test_override_not_applied_to_boss_or_rack_unless_flagged: a boss fight leaves the queue intact.
9. test_preview_equals_result_with_override: preview of the first enemy hit equals resolved damage.
10. test_override_enemy_swap_keeps_tier_hp_band: swapped enemy uses its own `hp_by_tier`.
11. test_no_global_randi_in_override_path: spy on RngService; zero draws from the `combat` stream when applying overrides.
12. test_override_extra_status_lands_on_enemy_wheel: ENCRYPTED on slice 0 at combat start.

**test_map_edits.gd**
1. test_add_node_connects_both_ways: new node on layer 3 has ≥1 in-edge and ≥1 out-edge.
2. test_remove_node_keeps_start_to_final_reachable: all choices on 20 seeded graphs keep a path.
3. test_remove_would_disconnect_is_refused: the edit is a no-op and returns a named reason.
4. test_retype_node_only_changes_type: id, layer and edges unchanged.
5. test_retype_visited_node_refused.
6. test_edits_apply_in_listed_order: remove then add on the same id differs from the reverse.
7. test_new_node_ids_deterministic: next id equals max id + 1, never RNG-based.
8. test_layer1_stays_all_routers: an edit adding a non-Router to layer 1 is refused.
9. test_final_rack_single_node_invariant: an add on layer 7 is refused.
10. test_edit_empty_list_is_noop_hash_equal: graph hash is unchanged.

**test_impromptu_fight.gd**
1. test_starts_combat_creates_fight_and_returns_to_map: after the win, the session is back on the same node and the event is marked resolved.
2. test_loss_ends_run_as_death: operative killed, Heat +10 + tier (existing rule).
3. test_impromptu_heat_zero_unless_authored.
4. test_impromptu_fight_uses_checkpointed_rng_stream: the stream state is saved before the fight and the enemy's first respin matches after reload.
5. test_rewind_cannot_cross_event_resolution: after the choice commits, undo to before the choice is refused.
6. test_rewind_inside_impromptu_fight_stops_at_start_checkpoint.
7. test_seeded_replay_event_chain_state_hash_equal: same seed and inputs (choice 2, fight inputs) twice give an equal hash.
8. test_impromptu_enemy_tie_break_by_content_id: a pool of equal weights picks by sorted id.

**test_n16_save.gd**
1. test_runstate_round_trip_with_queued_overrides: save → load equals the pre-save dict.
2. test_midfight_save_keeps_applied_override_not_requeued: reload does not apply it twice.
3. test_map_edits_persist_in_saved_graph.
4. test_old_save_without_field_migrates_to_empty_queue: fixture of the prior version; version bumps, queue is `[]`.
5. test_migrated_save_state_hash_stable_across_two_loads.
6. test_unknown_future_field_rejected_with_named_reason.

**test_event_consequence_flow.gd** (flow only)
1. test_event_choice_to_map_to_fight_flow: pick the choice, the map shows the edit, the next fight has the override chip.

**test_n16_sweep.gd**
1. test_sweep_200_seeds_no_unreachable_final: every event × every choice on 200 seeds.
2. test_sweep_replay_hash_equal_pairs: 50 seeds run twice.

## 4. Fixtures and helpers

## 6. Order

First write `test_next_combat_overrides.gd::test_hp_pct_arithmetic_exact` and `test_override_consumed_by_next_fight_only`. They fix the N2 interaction and the consume-once contract before any map or UI code exists. Then validation, map edits, and the save migration fixture (captured before the version bump).
