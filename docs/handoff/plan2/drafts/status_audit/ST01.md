# Status audit (ST-01, Q40)

## 1. Existing statuses

| status | rule (one line) | where in code |
|---|---|---|
| CORRUPTED | A needle on the slice doubles all of the owner's RAM costs (0 stays 0), with no corruption cap. The old self-damage is retired (R9, Q36). | ENCRYPTED | Each stack absorbs one incoming status apply of any other status, whatever its stacks, and is used up. ENCRYPTED on ENCRYPTED adds a stack. Hardened Firmware (permanent) absorbs every apply. | `effect_interpreter.gd:443-460` |
| OUTPUT_DOWN | Each stack takes an additive share of the slice's output (`output_down_factor`). Capped by `status_stack_cap`. | `combat_resolver.gd:1017, 1077-1079` |
| TIER_DOWN | Each stack lowers the landing tier one step (Perfect → Good → WEAK), floored at WEAK. Perfect hooks read the lowered tier. Capped by `status_stack_cap`. | `combat_resolver.gd:698, 1072` |
| PARASITE (retired) | Stored nowhere. `apply_status` converts it to OUTPUT_DOWN x`parasite_output_down_stacks` (2). The enum value stays for v2 saves. | `effect_interpreter.gd:450-451`, `parasite_handler.gd:3, 22` |

**Which list is right:** the code. `STORED_STATUSES` has five live statuses (CORRUPTED, OVERCLOCKED, ENCRYPTED, OUTPUT_DOWN, TIER_DOWN), and all five have live rules. The Q40 ruling names only three, but it was only discussing the new types and the stamp count. GDD 2.9 is stale on three counts. It lists three statuses and omits OUTPUT_DOWN and TIER_DOWN. It still gives CORRUPTED self-damage, which R9 and Q36 retired. It also says ENCRYPTED absorbs "the next status" without the per-stack and Hardened detail.

## 3. Recommendation

No new status ships. Fifteen of the sixteen rows are covered by an existing Status value (OUTPUT_DOWN for weak and frail, ENCRYPTED for artifact), by an effect or Firmware (Patch+, the amount modes, DEAL_DAMAGE listeners), or by a combat rule (enrage, SHIELD and SANDBOX, N6 listeners, N7 locks, R3 parking). Poison and burn are the Parasite ring's job (N10), so a creature-level tick would add a second damage path that bypasses R3 and the preview chip. The one real gap is **vulnerable**, defender-side amplification. No status touches damage taken, and `deal_hit` has no incoming multiplier. The smallest closure that avoids a new enum value is a **Parasite-ring anti-slice** (R8: "reduce your damage to the boss"). It would be the mirror: a ring segment on the enemy's wheel, latched by a player card, whose effect when read multiplies that wheel's incoming damage by `config: campaign_config.vulnerable_damage_pct` (placeholder 150). It is read at the needle, so it needs no persistent per-creature state, previews like any slice, and uses no RNG. If the designer wants it as a slot status instead, the next smallest change is one new `Status` value (append-only, so no save break), stored in `STORED_STATUSES`, with a `combat_resolver.gd` rule that scales damage taken by the victim's own slice stacks. That requires a save-version bump under N8 and tests for preview parity, and it uses the same `status_stack_cap` (`config: campaign_config.status_stack_cap`). Its stacking with Medicine ×4 and OVERCLOCKED must be sim-checked before it ships. Separately, update GDD 2.9 to list the five live statuses and the retired PARASITE alias.
