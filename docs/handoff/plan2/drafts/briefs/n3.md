# N3: Phases on every class, threshold parking, status keep, cleanse on enter, PARKED preview
- **Goal:** Every enemy class may carry phases (R1). While a phase is active, HP cannot drop below ceil(max HP × next threshold) on any loss path (R3). Statuses survive a layout change by centre-tick remap (R6). `cleanse_on_enter` is added. The preview exposes "PARKED −N" and equals the result.

## Acceptance
1. Validate: normal 0 phase entries, elite ≤1, mini-boss 2–3, boss 4–5 (counting the base phase as the spec table does). Thresholds strictly descend within (0,1). Each failure returns a named reason carrying the content id.
2. Floor = ceil(maxHP × next threshold). With max HP 100 and threshold 0.68: HP 80 hit 30 → 68; HP 80 hit 12 → 68 with parked 0; HP 68 hit 20 → 68 with 20 lost.
3. `deal_hit`, self-damage, parasite and pierce all go through ONE clamp helper. Pierce skips block/shield but not the floor. Heal is never clamped.
4. A multi-hit resolve: 3×10 from HP 75 → 68, 23 lost in total. The phase changes at the end of the resolve, and later hits in that resolve are also lost.
5. The last phase and normals have no floor: HP can reach 0.
6. `_apply_wheel_override` keeps statuses. Each moves to the new slice covering the old slice's centre tick; stacks on one slice merge. Existing tests that expected a wipe are updated.
7. `cleanse_on_enter` NONE/OWN/PLAYER/BOTH clears exactly the stated side's statuses, after the remap.
8. The preview model returns parked_amount and the post-clamp HP. A test compares it to the real resolve for single and multi-hit cases. A seeded replay hash is unchanged for fights without phases.
9. Threshold values and phase data live in content `.tres`. No magic numbers in code.
