# N4: Enrage (EnrageData, class defaults, HUD countdown chip)

- **Goal**
  - Add a turn-based enrage (R4) that raises enemy damage only.
  - Use additive steps (×1.25, ×1.5, …) with class defaults and an optional authored override per enemy.
  - Show a HUD countdown chip.
  - Preview must equal result.
- **Base / tag:** `<BASE_SHA>` / `<TEMP_TAG>`
- **Agent type and lane:** fix-rules. No Opus: the change is a pure step function plus one multiplier read, with no RNG.
- **Depends on:** none. N19 later reads the enrage step; N3 (phases) is independent.

## Files
- `scripts/data/enrage_data.gd` (new): `start_turn`, `every_n_turns`, `damage_pct_step`, `validate()`, `enrage_step(turn)`, `enrage_multiplier(turn)`.
- `scripts/data/enemy_data.gd`: optional `enrage` field; `validate` rejects enrage on normals.
- `scripts/data/campaign_config_data.gd` and `content/config/campaign_config.tres`: `enrage_defaults`.
- `scripts/core/combat_resolver.gd`: `start_turn` stores the step on the enemy CombatantState; the multiplier is applied in the shared damage path used by both resolve and preview.
- `scripts/core/` (rule-side): `enrage_chip_state(combat)`.
- HUD: one chip widget, a TextDb key, and `strings.csv` (re-exported). Find the HUD files via `context_slice.py --deps`.
- `content/enemies/the_handler.tres`: authored enrage, start 8.
- `tests/test_manifest.json`

## Acceptance
1. Defaults: boss and mini-boss 10 / 5 / 25 %, elite 8 / 5 / 25 %, normal off. All values live in the `.tres`.
2. Lookup order is authored, then class default, then off.
3. Multiplier = 1 + step × pct. Turn 9 gives step 0, turn 10 gives 1 (×1.25), turn 15 gives 2 (×1.5), turn 20 gives 3 (×1.75). Turn 10000 stays finite.
4. A base hit of 10 on turn 10 deals the value `_scaled` rounding yields. The test pins that constant.
5. Enrage never changes heal, block, shield or the player's damage. A 2 % hub heal is identical at step 2.
6. Calling `start_turn` twice on one turn leaves the same step. Preview chip number equals actual HP lost at steps 0 to 3.
7. The step is derived from the turn counter. A save round trip, a rewind inside a turn and a seeded replay give identical hashes. No RNG stream is read.
8. `validate()` errors name the offending field (`start_turn` < 1, `every_n_turns` < 1, negative `damage_pct_step`). Normals with enrage are rejected.
9. The chip is hidden for normals and shows "turns to next step" plus the current ×N. It reads only `enrage_chip_state`.
10. All 57 enemies pass validation. Text is US English through TextDb keys.

## Designer rulings 2026-10-18 (override the text above; DECISIONS "decision sheet" Q33, Q16, Q29)
- **No countdown chip.** Enrage is shown only once active, as a **buff on the enemy** (×N step) with a tooltip that
  explains it (and when the next step comes). Acceptance 9 becomes: no enrage UI before step 1; at step ≥ 1 a buff
  icon on the enemy reads the step and its tooltip text comes from TextDb. `enrage_chip_state` → `enrage_buff_state`.
- Steps stay **additive**; Pressure is dropped in favor of EnrageData (remove any Pressure path you find, or list it).
- **Resistance gain is an enrage option:** EnrageData gets `resistance_step` (int, default 0) besides
  `damage_pct_step`; each step adds that much to the enemy's per-turn resistance (N21 owns the refresh; until N21 lands,
  add it to the existing start-of-turn restore). Class defaults stay damage-only; the field is for authored enrages.
- Bosses are the longest fights: tune enrage before any phase-HP change (Q29); numbers stay in the `.tres`.
