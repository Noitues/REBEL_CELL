# N13: Fixed satellites + replacement

- **Goal**
  - Satellites are fixed to their slice. `validate_action` refuses any player action that would move a satellite's wheel unless `can_move_satellites` is granted (class, Firmware or Daemon).
  - Undock is scoped to that flag.
  - Docking onto an occupied slice follows `on_occupied` (default keep, or REPLACE). This amends GDD 2.7 (R12).
- **Base / tag**: `<BASE_SHA>` / `<TEMP_TAG>`
- **Agent type and lane**: fix-rules. Sonnet; no OPUS-BECAUSE (no RNG or hash-contract change).
- **Depends on**: none.

## Files
- `scripts/data/satellite_spawn_data.gd`: add `on_occupied` (KEEP, REPLACE; default KEEP) and validate it.
- `scripts/core/combat_resolver.gd`: `_spawn_satellite` and `validate_action` only.
- `scripts/core/undock_handler.gd`: scope to the flag.
- Class, Firmware and Daemon data scripts: add a bool `can_move_satellites`, default false.
- One query function, `can_move_satellites(state)`, OR-combining the three sources. Put it beside `validate_action` in `combat_resolver.gd`.
- The Firmware and Daemon `.tres` content that grants the flag is the designer's call. Do NOT author any (see Q below). Use only test fixtures.
- `strings.csv` reason text via `tools/export_text.gd`.
- Satellite-wheel nudge arrows disabled with a toast: view glue, minimal.

## Acceptance
1. A satellite NUDGE, SPIN, FLIP, RESPIN, FREEZE or SNAP without the flag is invalid with reason `SATELLITE_FIXED`. The state hash is unchanged after the refusal, and enemy resistance is untouched.
2. With the flag from the class, Firmware or Daemon, a satellite nudge moves exactly 1 tick. The flag is OR-combined, so two sources still move it 1 tick. Unequipping the Firmware refuses the move again.
3. A host spin of 7 and a host flip keep the satellite on the same slice, with its mini-wheel rotation unchanged. A host respin draws the RNG once per host wheel, never per satellite.
4. With 0 satellites, no new refusals appear anywhere.
5. REPLACE: a spawn on an occupied slice removes the old satellite and docks the new one. The old one counts as destroyed, so existing satellite-destroyed hooks fire for it (placeholder; see Q). KEEP leaves today's behavior.
6. Undock is refused without the flag. With it, it affects only a satellite the player may move.
7. `satellite_spawn_data.validate` rejects an unknown `on_occupied` value.
8. The spawn preview equals the result. Undoing a staged spawn or move restores the prior satellite. Seeded replay hash is identical across runs and across a save/load round trip.

## Designer rulings 2026-10-18 (override the text above; DECISIONS "decision sheet" Q7, Q10)
- **Replaced = destroyed, always.** Max 1 drone or satellite per slice. Installing on an occupied slice destroys the
  old one and installs the new one. There is no KEEP mode and no `on_occupied` field: drop them (acceptance 5, 7 change
  accordingly). If shipped content relied on keep-on-occupied, list it in `notes`.
- **New keyword trigger `ON_SATELLITE_DESTROYED`** (append-only in `rc.gd`), fired for every destroyed satellite or
  drone (killed, replaced, cleared). One test hooks it from a fixture. No content uses it yet.
- **Undock is a global keyword**, not a class/Firmware/Daemon flag: drop `can_move_satellites` and its three data
  fields. A satellite moves only through an effect that carries the Undock keyword (today's `undock_handler` card);
  every other player action that would move a satellite is refused with `SATELLITE_FIXED` (acceptance 1). Acceptance 2
  and 6 become: an Undock-keyword effect moves it exactly 1 tick; no other source does. Keep the keyword data-driven
  (one bool or tag on the card/effect data, logged in DECISIONS per CLAUDE.md rule 8, check in
  `tools/schema_smoke_checks.gd`).
- Satellites stay fixed on the slice they were installed on through host spins, flips and respins (acceptance 3).
- **Not in scope:** the class with the satellite Hub passive, and **Hangar** (a wheel-wide passive over all slices of
  its wheel): both are later content passes.
