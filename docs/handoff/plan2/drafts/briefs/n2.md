# N2: Tier base-value tables (HP bands, damage table, band validator)

- **Goal:** Tier sets base values only (R2). Add `hp_by_tier` and boss `hp_bands` to enemies and the tier tables to the campaign config, replacing the three conflicting damage scales (GDD 1.2^(t−1), config 1.3, schema default 1.6) with one table. Add a band validator plus a lint test over `content/enemies/`. Fold HP and damage scaling into table reads. No enemy re-authoring and no balance changes beyond the table swap.

## Acceptance
1. `enemy_damage_by_tier` = [1.0, 1.3, 1.69, 2.2], `reference_dpt_by_tier` = [9, 11, 14, 18], `target_turns_per_phase` = 3.5; all live in `campaign_config.tres`, none in code.
2. A fresh `CampaignConfigData.new()` has the same table (no 1.6 default). Accessors clamp tiers below 1 and above 4.
3. `EnemyData.hp_by_tier` has 4 entries. `validate()` rejects wrong length and any value outside the class band with a named reason (e.g. "hp_by_tier[2] 43 outside normal band 44-56"). A mini-boss T4 entry is rejected.
4. Boss `hp_bands` is sorted by ascending zone ceiling. `hp_for(multiplier)` returns Genome Core 300/330/360/400 at 1.00/1.15/1.30/above. The last ceiling must be open-ended.
5. `enemy_scale()` and `enemy_output_scale()` read the tables. Output equals the old 1.3^(t−1) within 0.05 at every tier. Legacy enemies with no `hp_by_tier` keep their current HP (fallback), so no fight changes before the re-author passes.
6. `create_combat` starting HP comes from the table; the preview chip equals the real result in a seeded replay.
7. The lint test checks every `content/enemies/*.tres` that sets `hp_by_tier` at all four tiers. A drift guard fails if the lint helper's band numbers differ from the R2 table. Non-migrated enemies are listed as a warning, not a failure.
8. Same seed → identical results; save round trip unchanged. The config stays a read-only Resource, and no RNG stream is read or advanced.
