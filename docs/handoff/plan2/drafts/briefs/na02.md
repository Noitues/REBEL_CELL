# NA-02: Netrun art data contract (JSON, schemas, art seeds)

- **Goal:** Define and export the data contract the netrun art consumes: `city.json`, `net.json`, `run_graph.json`, `key_locations.json`, `art_seeds`, and `derive_<run>.json` v1. Ship JSON Schemas for each. Art seeds use FNV-1a 64 over [layout_seed, "art/"+stream, keys]. They never read or advance a gameplay RNG stream. Building ids are unique.
- **Base / tag:** `<BASE_SHA>` / `<TEMP_TAG>`
- **Agent type and lane:** fix-rules, plus a fix-mechanical exporter in the same slice.
  - OPUS-BECAUSE: a derived art seed must not perturb the saved RNG streams, so determinism and save compatibility are at stake.
- **Depends on:** NA-01

Read first: `docs/handoff/netrun_art/` spec §2.2, §2.3, §3.5, §3.6, §11.5, and `docs/handoff/plan2/NA02_FIELDS.md`. That file (the orchestrator writes it) must list every field, type, and unit per JSON file, the `derive` v1 keys, and the stream names. Do not invent fields beyond it. If it is missing, report BLOCKED.

## Files
- new `scripts/core/art_seed.gd`: pure RefCounted, FNV-1a 64 `derive(layout_seed, stream, keys)`.
- new `scripts/state/netrun_art_export.gd`: builds the five JSONs and derive v1 from campaign and run state, read-only.
- `scripts/core/netrun_session.gd`: one hook that calls the exporter. This is a shared file (see Conflicts).
- new `tools/netrun_art/schemas/*.schema.json`: one schema per file, with `version: 1`.
- new `tools/netrun_art/export_contract.gd`: headless CLI writing to `%TEMP%`.
- `tests/test_manifest.json`.

## Acceptance
1. The same seed exported twice, and in a fresh process, gives byte-identical JSON (sorted keys, fixed float format, LF).
2. `ArtSeed.derive` matches the FNV-1a 64 vectors in `NA02_FIELDS.md` for ≥ 10 inputs. It takes no `RngService` parameter.
3. Golden replays: the RNG stream state hashes after an export are identical to those after no export. Test at 3 seeds, across save and reload.
4. Exporting a run changes no saved field. The save version is unchanged and old saves load.
5. Every building id in `city.json` is unique across 1,000 seeds, with 0 collisions.
6. Every JSON validates against its schema. A mutated fixture (missing key, wrong type, duplicate id) is rejected.
7. `run_graph.json` matches the `map_graph` nodes and edges 1:1 (count and ids). It carries `version: 1` so N16 can bump it.
8. `key_locations.json` lists every Exploit Site with an existing building id. It uses the Exploit semantics available now; B2 and D5 may change them later.
9. The art seed for a given (layout_seed, stream, keys) is independent of call order (shuffled-order test).
10. Exporter time is ≤ 50 ms for a 40-Site city (print the measured value).
