# G1–G16 re-evaluation: preparation sheet

**Purpose.** The designer holds a re-evaluation of the G1–G16 mechanic proposals after the M14 art
integration (`docs/DECISIONS.md` 2026-10-05, "Designer rulings: art reintegration, pause point 0", ruling 8:
"The G1–G16 mechanic proposals are re-evaluated with the designer after the art integration. Until then art
for them stays in `docs/art_reference/`"). This sheet collects what the designer needs in one place. It is
neutral and factual: **no proposal is approved, rejected or ranked here as a decision.** Each proposal needs a
ruling (approve / reject / later); an approved one becomes a G-pass (rules in `scripts/core/` with tests,
content, a balance sim, then its art), per `docs/ART_REINTEGRATION_PLAN.md` §3.2.

**Sources merged.**
- `docs/ART_REINTEGRATION_PLAN.md` §3.2 (the G1–G16 table; the batch notes in §4 that say which art waits for
  which G; the suggested order near the end of §4).
- `docs/concepts/GDD_ART_COVERAGE.md` §2 (missing designs) and §3 (mismatches between the concepts and the GDD;
  its "To-do?" column says whether DIRECTION_REVIEW lists the item).
- `docs/ART_BIBLE.md` Appendix B (open game-design to-dos that affect art), items 3 to 11.

**How to read the columns.**
- *Current rules* cites GDD sections as they stand today (after the M14 ART-0 names pass: SHIM / OVERFLOW /
  DEFRAG / DETOUR / SANDBOX / TROJAN / HOTFIX / INFECT / NULL, TAKEN / DOWN, Mainframe, Central Server).
- *scripts/core* names the classes that would change, read from the code at `ecf6e16`. `scripts/data/`
  resource changes are listed with it because CLAUDE.md rule 8 asks for a smoke-check and a DECISIONS entry for
  each. `scripts/state/` is named where runtime state would need a field. "Content" means `content/*.tres`.
- *Art that waits* lists files under `docs/art_reference/` (curated; the rest stays on tag `art-concepts-r43`).
  Where nothing was copied, the cell says so.
- *Size* is a rough estimate of the rules work only, excluding the art port: S = one class or a few
  functions plus tests, no schema change; M = several classes, a schema change, content and a balance
  check; L = a new subsystem or a change to generators and several state classes, with a balance simulation.
- *Order* is the plan's own suggested order (plan §4, the last "suggested order" line: G11, G6, G2, G1, G4/G5,
  G3, G14, G8/G9, G12, G7) with the items the plan does not place (G10, G13, G15, G16) slotted by dependency.
  It is a starting point for the discussion, not a decision. Items shown "n/a" have no rules work or no design.

## 3. Cross-cutting notes for the meeting

- **Shared state model.** G1 (double status), G2 (×N stacks) and G4 (new statuses and slice states) all touch
  `WheelState.slice_statuses` (one `RC.Status` per slot today) and `EffectInterpreter.apply_status`. A single
  status model would serve all three; the order above (G2, then G1, then G4) puts the stack decision first.
- **Tier naming.** G5 introduces slice tiers I–III next to netrun / Site tiers T1–T4 and Upgrade tiers; the
  names pass already fixed Roman numerals for upgrades and T-numbers for Sites (DECISIONS pause point 0, ruling 6.3).
- **Balance.** G1, G3, G5, G8, G9, G12 each shift balance and need `CampaignSimulator` runs and, for the
  rules, the GDD changes logged in `docs/DECISIONS.md`. G10, G13 and G16 do not.
- **Determinism.** G3, G9, G11 and G12 add state that must serialise (`to_dict` / `from_dict`) and draw RNG only from
  `RngStreams`; replays (`CombatReplay`) must match.
- **No art is shipped for any G until it is approved.** The placeholders (`glyphs/placeholder_*`, the
  state overlays) are reference only (ART_BIBLE v2 3.5).
